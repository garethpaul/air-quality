# Redis Python Client 8.0.1 Update

Status: Completed

## Problem

The service pins redis-py 8.0.0 while the upstream project published the 8.0.1
bug-fix release on June 23, 2026. The repository roadmap requires direct
dependencies to remain current on supported Python versions.

## Requirements

1. Update only the direct Redis client pin from 8.0.0 to 8.0.1.
2. Keep the runtime dependency set exact and preserve existing cache behavior.
3. Verify the resolved dependency graph and audit on Python 3.12 and 3.14.
4. Add mutation-sensitive contracts for the exact pin and completion evidence.

## Evidence

- PyPI publishes redis-py 8.0.1 for Python 3.10 and newer, including Python
  3.12, 3.13, and 3.14 classifiers.
- The upstream 8.0.1 release is a patch containing bug fixes and maintenance
  updates without a documented minimum-Python change.
- Release: https://github.com/redis/redis-py/releases/tag/v8.0.1
- Package metadata: https://pypi.org/project/redis/8.0.1/

## Scope Boundaries

- Do not change cache keys, Redis URLs, retry behavior, serialization, route
  behavior, or any other dependency.
- Do not claim live Redis integration from the dependency-free unit tests.

## Verification

- The baseline checker failed when it required `redis==8.0.1` while the
  manifest still pinned 8.0.0.
- Repository and external-directory `make check` passed with the reviewed
  interpreter and exact dependency set.
- Five isolated hostile mutations were rejected for the Redis pin, completed
  status, upstream version evidence, Python compatibility, and full-gate
  evidence.
- Hosted Python 3.12 and 3.14 checks and CodeQL are required before merge.
